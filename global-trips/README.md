# JT & QX’s Global Trips

## 系统分层

- ChatGPT Project / 旅行线程：研究、讨论和形成候选。
- `trip.json`：已确认的酒店、路线与清单基线。
- HTML / JavaScript：读取 Trip Data 并提供 Plan、Live、Memory 三阶段界面。
- 独立 Worker + D1：登录后的五态采购状态、已打包勾选、待办、预算和笔记的共享数据源。
- 浏览器缓存：保存未上传的修改和用户选择记住的登录凭据；页面明确显示云端保存是否成功。

## 网页编辑

在“登录以编辑”输入专用旅行登录码后，编辑会自动保存。其他设备使用同一登录码即可读取；页面打开、回到前台或点击“刷新 / 重试”时同步。旧浏览器记录通过“导入本机旧记录”确认后迁入。两个设备修改同一字段时，先选择采用云端内容或保留本机修改。

未登录访问仍显示公开行程基线，私人编辑不公开。部署和验收说明见 `services/trip-sync/README.md`。`cloud-config.json` 的 `apiBase` 为空时表示云服务尚未接通，不能视为已上线。

## 线程同步约定

每趟旅行使用稳定 Trip ID，例如 `2026-maldives-bangkok`。在任意相关线程中，当结论已经确认时，使用：

```text
同步到 Trip 001
```

Codex 应从可访问的旅行线程提取本轮已确认变化，整理为最小 Delta，写入对应 `trip.json`；如果数据结构新增字段，同时更新该 Trip 的渲染与校验。运行：

```bash
node scripts/validate-global-trips.mjs
```

验证通过后再单独提交和发布。讨论、候选价格、未确认预订不得自动覆盖确认事实；不得把聊天链接、账号信息、证件号、订单号、确认号、保单号或支付凭证写入公开仓库。

普通 ChatGPT Project 记忆只提供上下文，不是自动同步数据库。ChatGPT 线程不能直接写入 GitHub 时，确认 patch 仍停留在线程或附件里；可由 Codex 读取可访问的线程并提交发布，不需要用户逐条搬运。目前不会监听全部聊天；ChatGPT 直接调用云端写入接口与 QX 独立账号尚未接入。网页编辑通过独立 API 保存，不需要 GitHub Token。
